# Fulcrum（支点）— 商业模式规划

**发行方：** TuringLambda AI（`turinglambdaai`） · **状态：** 0.1 草案，2026-09-28 · **语言：** 中文（与英文版完全对应） · English: [business.md](business.md)

Fulcrum 是一款键盘优先的启动器（Raycast 式命令面板），覆盖 macOS、Windows 和 Linux，基于 [Rivet](https://github.com/turinglambdaai/rivet) 构建：每个应用内嵌同一套共享的 Racket 后端，各平台使用第一方原生 UI（SwiftUI / WinUI 3 / GTK4）。不用 Electron，不用 WebView。

文中标注 **(S)** 的事实均来自公开来源（见[资料来源](#13-资料来源)）；标注 **(E)** 的数字均为规划估算，不是实测数据。凡是拿不到的数据，本文会明确说明，不做编造。

## 2. 市场与问题

### 启动器为什么重要

启动器是桌面上使用频率最高的工具：它盘踞在应用切换、搜索、剪贴板、文本片段和快捷操作的路径上，每天被触发几十次。正因为高频，用户愿意为它付订阅费——这个品类养得起收费产品（Raycast Pro、Alfred Powerpack、uTools 会员，证据见下）。

### 需求验证

我们不需要证明"有人为启动器付费"，Raycast 已经在 macOS 上证明了这一点（S）：

- 三轮融资共约 $48M，其中 2024 年 9 月的 $30M B 轮明确用于跨平台扩张与 AI（S）。
- 扩展商店拥有 2,500+ 开源扩展，每周新增数十个（2026 年 7 月某一周新增 32 个）（S）。
- Pro 档 $8–10/月起，最高到 $50/月的 Max 档——证明用户愿意为这块面板每年支付 $96–600（S）。

**TAM 框定（明确自下而上，不存在权威数字）：** 我们没有找到桌面启动器品类任何可信的公开 TAM 数据，也不会编造一个。诚实的框架是把启动器当楔子，而不是当 TAM：

1. **锚定价格带：** 现有付费启动器用户的年支出大致在 $46–600 之间（Alfred 一次性 £34–79 ≈ Pro 订阅 3–4 年；uTools ≈ 每年 ¥228–328 量级；Raycast Pro $96/yr）（S）。Fulcrum Pro 定价 $72/yr 落在已被验证的价格带内。
2. **扩展性：** 启动器是后续一切功能的信任入口（片段同步、AI 命令、团队片段库）。品类本身小，但留存面不小。
3. **缺口：** 楔子存在的原因是各平台默认工具（Spotlight、开始菜单/Command Palette、GNOME 时代遗留物）要么封闭、要么插件能力平庸，且没有任何跨平台产品在三个平台上同时做得出色。

### 客户是谁

三个重叠的人群，按优先级排序：

1. **开发者与工程师** —— 滩头阵地。他们每天使用启动器、容忍类 CLI 工具、并且会写插件。Raycast 的扩展生态就是开发者写给开发者的（S）；我们从他们所在的地方开始。
2. **跨平台高阶用户** —— 在两三个操作系统之间生活的人（咨询顾问、系统管理员、家里 Linux / 公司 Mac）。他们今天要么每台机器装不同启动器，要么将就更差的工具。这是目前没有任何竞品服务的人群，也是把楔子写成具体的人的样子。
3. **中文技术用户** —— V2EX/少数派/linux.do 上被 uTools 养起来的人群，对价格敏感，也对 Electron 与本地优先的取舍敏感。

由此得到的产品决策规则：v0.x 的每个功能必须服务人群 1 或 2；人群 3 的变现等第二阶段（§5）。

### 三平台缺口

| 平台 | 当前最佳选项 | 缺口 |
|---|---|---|
| macOS | Raycast（稳定版，S） | 闭源、仅 Mac、捆绑 AI 的订阅制 |
| Windows | PowerToys Command Palette / Flow Launcher（S） | 免费且够用，但没有跨平台对等体验，没有高级 AI/同步层，微软的优先级不等于高阶用户的优先级 |
| Linux | Ulauncher 及 rofi 系工具 | 2026 年围绕 Ulauncher 几乎没有可见动作（S）；Raycast 级别的产品完全空缺 |

跨平台就是楔子：一次购买、一份片段库、一套肌肉记忆，三个操作系统。这既是产品存在的理由，也是每一场竞品对比中都能站住的卖点。

## 3. 产品与楔子

Fulcrum 具体是什么：

- **键盘优先命令面板** —— v0.1.0 内置应用模糊搜索、剪贴板历史、文本片段、计算器、网页搜索 bang、系统命令。
- **各平台第一方原生 UI** —— macOS 用 SwiftUI，Windows 用 WinUI 3，Linux 用 GTK4。Windows 版就是 Windows 应用，macOS 版就是 macOS 应用。不是 WebView，也不是假装原生的控件库。
- **同一套 Racket 后端** —— 各平台共享同一份嵌入式 Racket CS 后端逻辑，经 Rivet 协议桥接，由代码生成产出类型化原生客户端。业务逻辑只写一遍。
- **隐私 / 本地优先** —— 搜索索引、剪贴板历史、片段全部留在设备上。云同步与 AI 是可选的增值服务，永远不是前置条件。
- **语言无关插件** —— FPP1：JSON over stdio，每个插件一个独立外部进程。插件可以用 Python、Rust、Go、Node 甚至 shell 脚本写，不要求 JavaScript 单一文化。

它在用户唯一感知的维度上胜出的原因：原生 UI 更快、行为与操作系统一致；本地优先是用户可验证的隐私姿态（核心功能无需账号）；FPP1 相对专有 JS API 降低了插件作者的门槛。

### 为什么这可能失败（诚实段落）

习惯型产品里，分发能力压倒打磨程度，而我们两者都从零开始。Raycast 手握 $48M、2,500+ 扩展、已经落到用户手里的 Windows beta，以及独占这个搜索词的品牌（S）。我们的 Linux 优势对应的是三个市场中最小的一个，而微软随时可能把 Command Palette 做到对多数 Windows 用户"够好"。我们的付费功能（同步、AI）没有差异化——用户已经在向 Raycast 买同样的东西。Racket 是交付与招聘风险：写我们这套后端它极好，招人它极难。楔子本身也可能反转：如果 Raycast 在我们 1.0 之前发布 Windows 稳定版，我们的头衔就变成"Linux 那一个"，那是更小的生意。我们仍然认为值得试，因为"跨平台原生启动器 + 免费本地核心"这个位置上没有在位者——但这段话就是这句话的诚实版本。

### 诚实的缺口

- **Rivet 目前没有 Linux 宿主。** Rivet 0.2 只面向 WinUI 3 与 SwiftUI；Fulcrum 的 Linux 版需要 Rivet 提供尚不存在的 GTK4 宿主。它已排期（§12），但尚未实现；0.1 是 macOS + Windows。
- **v0.1.0 没有 AI、没有同步、没有商店。** MVP 刻意朴素：搜索、剪贴板、片段、计算器、bang、系统命令、FPP1。
- **没有用户、没有收入、没有实测转化数据。** §9 的每个数字都是模型假设，一律标注（E）。
- **商标与域名清查尚未启动**（§11）。

### 我们不竞争什么

明确不做的事：

- **Raycast 的扩展生态深度。** 2,500+ 扩展是五年社区积累的护城河（S）。第一年我们不会追平；FPP1 + AI 辅助移植是缓解手段，不是追平宣言。
- **macOS 上的系统级深度整合。** Spotlight 和 Raycast 永远比我们更"macOS 原生"。我们竞争的是跨平台同一性，不是 Mac 深度。
- **Windows 文件搜索的统治力。** Everything/Listary 拥有 NTFS 即时搜索；我们索引应用与内容，不索引整个磁盘。
- **前沿 AI 质量对等。** Raycast Advanced AI 捆绑顶级模型；我们第二阶段的捆绑推理以小模型为默认，其余一律 BYOK。我们卖的不是最强聊天机器人。
- **企业 MDM/设备管理。** Teams 档是授权 + 共享片段，不是 MDM 平台。
- **把服务型产品卖成一次性买断。** Alfred 的一次性 Powerpack 对无服务器成本的 Mac 独占工具是好买卖；同步和 AI 有持续性成本，我们无法诚实地承诺永久。

### 新进入者与相邻动作

- **Sol** 等开源 Mac 启动器持续出现（S）；没有一个做到"跨平台 + 原生 UI"，而这正是我们楔子所在的那道门槛。
- **Raycast Glaze**（用 AI 构建原生桌面应用的工具，S）是一个信号：Raycast 正在加注原生桌面。盯住它：它可能成为竞争者或渠道，无论哪种都验证了原生 UI 论点。
- **操作系统原生默认项持续变好**（Spotlight、Command Palette）。它们向大众用户"够好"收敛的速度，和我们为高阶用户增加深度的速度相当。这正是免费档必须是完整本地产品而非演示版的结构性原因。

## 5. 商业模式 — 开放核心

### 授权（建议）

| 组件 | 许可证 | 理由 |
|---|---|---|
| 核心仓库（`fulcrum`） | **BUSL-1.1**，每次变更 4 年后自动转 MIT | 用户可以阅读、审计、打补丁、自行构建——隐私产品必须允许这些——但在独占期内，竞争者不能把我们的核心装进竞争产品 |
| 插件 SDK + FPP1 规范 | **MIT** | 生态层必须零摩擦；协议的普及比控制权更值钱 |

备选方案：**纯 MIT** —— 采用度与善意最大化，但在我们弱小时毫无保护；**AGPL-3.0** —— 对桌面软件很别扭，且吓退插件作者；**闭源专有** —— 直接杀死本地优先的信任叙事。带 4 年 MIT 转换的 BUSL 是标准的折中；我们会显著标出转换时间，不让人感觉被套牢。

### 分层与确切的功能拆分

| | 免费版 $0 | Pro $8/用户/月，或 $72/用户/年（E） | Teams $12/用户/月 |
|---|---|---|---|
| 本地功能 | **全部本地功能、无限制、永久**：应用搜索、剪贴板历史、片段、计算器、bang、系统命令、FPP1 插件 | 同左 | 同左 |
| 剪贴板历史 | 本地、无限制 | 本地、无限制 | 本地、无限制 |
| AI 命令 | 仅 BYOK（第一阶段）——对我们零成本 | 捆绑推理（第二阶段），带公平使用护栏 + 可选 BYOK | 捆绑 + BYOK |
| 云同步 | — | 设置 + 片段同步 | 团队共享片段库 |
| 主题 | 内置少量 | 全套主题 + 自定义 | 全套主题 |
| 抢先体验 | — | 新功能先进 beta 渠道 | 同左 |
| 管理 | — | — | 席位管理、集中计费/授权，后续 SSO |
| 支持 | 社区 | 邮件、尽力而为 | 优先支持 |

免费版就是完整的本地产品。付费墙只立在真正产生成本的服务（同步、捆绑 AI）和便利项（主题、抢先体验）上。这条线会写在定价页上，以避免 uTools 已被记录在案的"变相收费"式反弹（S）。

### 定价依据

- **为什么是 $8/$12：** Pro 在年付口径上落在或低于 Raycast Pro 的 $8–10/月 价格带（S），同时是一个真实的付费产品；Teams 用标准的约 1.5× 席位倍数，不预设我们之后要兑现支持承诺的企业功能。
- **为什么不再便宜：** $3–4 档会让支持面积翻倍，收入却只多一个舍入误差；同步和捆绑 AI 有真实单位成本（§6、§9）。
- **试用与退款：** Pro 试用 14 天、无需信用卡；30 天无理由退款；通过吊销许可控制滥用。
- **刻意推迟的事项：** 购买力平价区域定价（中国——见上方第二阶段说明）、教育折扣、兜底永久授权——都在 1.1 用真实数据复盘，而不是靠观点决策。

### 一次性终身买断档 — 分析与建议

$150 早鸟终身许可，限前 1,000 份，仅在 1.0 窗口期出售：

- **算术（E）：** Pro 年付 $72，按约 75% 的付费用户年留存假设 → 三年期望 Pro 收入 ≈ $167。$150 终身买断与三年 Pro 收入大体打平，在发布期前置现金，并奖励最早的支持者。
- **成本安全：** 终身买断**不含捆绑 AI 推理**（BYOK 永久可用）。个人云同步的存储成本微不足道（约每用户每年 $0.1–0.5，E）。因此终身用户的边际成本接近零。
- **备选：**（a）不设终身档 —— 经常性收入更干净，但 1.0 发布缺乏爆发点，错过 Alfred/uTools 买断型买家的心理；（b）终身含 AI —— 不可封顶的推理负债，否决。
- **建议：** 卖，设限额，仅限 1.0 窗口，排除 AI，明确标注"支持者许可"。限额售罄后复盘。

| 费率 | 约 2.9% + $0.30（E） | 约 5% + $0.50（E） |

## 6. AI 策略

**第一阶段（0.3）— 仅 BYOK。** 用户自带 OpenAI/Anthropic/本地 Ollama 密钥；请求从应用直达供应商；我们的成本为零，隐私姿态保持干净。AI 功能以用户自有密钥为开关，因此 AI 永远不会成为推迟发版的原因。

**第二阶段（1.0+）— 捆绑推理**（Pro 专享），带护栏：小模型/默认模型优先、提示词缓存、单用户月度成本预算（约 $1/用户/月，E）、可见配额表、超限自动降级到 BYOK。绝不把前沿模型打包进固定价（Raycast Advanced AI 加购 $16–20/月，S——这就是那条定价线的成本信号）。

各阶段具体交付的 AI 功能：

| 功能 | 阶段 | 形态 |
|---|---|---|
| 自然语言系统命令（"静音一小时"） | 0.3 | 本地意图匹配优先，模型兜底 |
| 剪贴板变换（摘要、清洗、翻译） | 0.3 | 经 BYOK 走用户自己的模型 |
| 从示例生成片段 | 0.3 | BYOK |
| 快速 AI 问答（注入选中上下文） | 1.0 | 捆绑小模型，带护栏 |
| 插件脚手架（`fulcrum new plugin` + 描述） | 1.1 | BYOK 或捆绑；为 §7 供给端输血 |

**单活跃用户成本估算（E —— 四个输入全是假设）：**

| 假设 | 取值 | 依据 |
|---|---|---|
| 每次 AI 命令的 token | 约 600 输入 + 300 输出 | 启动器提示很短；系统提示走缓存（E） |
| 中位使用量 | 20 次/月 | 习惯频次估算（E） |
| 重度使用量 | 200 次/月 | p95 估算（E） |
| 小模型 API 价格 | 约 $0.15/M 输入，$0.60/M 输出 | 小型快速模型，量级估计（E） |
| 中档 API 价格 | 约 $3/M 输入，$15/M 输出 | 主流托管模型（E） |

| 情景 | 成本/用户/月 |
|---|---|
| 小模型、中位（20 次） | ≈ $0.005 |
| 小模型、重度（200 次） | ≈ $0.05 |
| 中档、中位 | ≈ $0.13 |
| 中档、重度 | ≈ $1.26 |

结论：捆绑 AI 只有在"小模型默认 + 硬性公平使用上限"下才付得起；中档模型重度情景（约 $1.26/月）正是护栏边界。§9 的第二阶段 AI 支出按约每付费用户 $0.30–0.40/月混合建模（E）。

## 7. 插件与市场策略

排序先行，并设明确门槛——商店是后置的收入线，不是发布功能：

1. **FPP1 永久免费开放（MIT）。** 不设独占 API，不给协议功能上付费墙。协议规范随 v0.1.0 发布。
2. **发布期手工画廊（0.2）：** 静态、人工审核的一方 + 社区插件目录；UI 内安装；无支付。一方插件覆盖头部用例（GitHub issues、Jira 搜索、Docker 控制、包管理器），保证目录从第一天起不空。
3. **带 70/30 分成的精选商店 — 之后。** 付费插件上线的前提：(a) 画廊 ≥300 个条目，(b) WAU ≥10k，(c) 计费通道已在自有 Pro 销售上得到验证，(d) 自动化插件审核（权限清单、沙箱默认、恶意软件扫描）就绪。70/30 优于行业惯例的 85/15，把激励倒向供给侧。

门槛条款是产品的诚实机制：没有受众的付费商店是一座死城，会毒化整个生态叙事。

0.2 画廊规划的一方插件——每一个同时是 FPP1 协议的参考实现，协议文档就靠它们写出来：

| 插件 | 为什么先做 |
|---|---|
| GitHub（issue/PR 搜索） | 开发者滩头 |
| Docker 控制 | 启动器被点最多的能力之一 |
| 密码管理器（只读、本地 vault API） | 信任面；vault 内容绝不进我们的云 |
| 单位 / 正则 / 时区转换 | 近零成本，验证 FPP1 的人机工效 |

商店的权限模型：插件在清单（manifest）中声明能力（网络主机、shell 执行、剪贴板读取、钥匙串访问）；安装时 UI 明示；能力项以用户同意为门槛。画廊阶段接受"已声明未强制"；商店上线必须强制沙箱（§7 第 3d 条）。

**以下全部数字均为模型推算，非实测 —— 全部标注（E）。** 不含人力成本（创始人 + 小团队；本模型展示的是直接成本可行性，不是薪资方案）。

### 假设清单（把假设全部摆出来）

| 假设 | 取值 | 标注 |

|---|---|---|---|---|---|---|---|---|---|
| **年份** | 1 | 2 | 3 | 1 | 2 | 3 | 1 | 2 | 3 |

## 10. 指标

仅采集选择加入（opt-in）的遥测，默认关闭，安装前用一屏明确说明上报内容并公开 schema。本地优先的产品不能在遥测上装糊涂；它只能做到**自愿**。

| 指标 | 定义 | 目标 |
|---|---|---|
| 激活 | 安装后 5 分钟内完成首次成功搜索 | ≥ 80%（E） |
| WAU / MAU | 周活跃 ÷ 月活跃 | ≥ 0.6 —— 启动器应当是每日习惯型工具（E） |
| 无结果率 | 返回空结果的搜索占比 | < 10%，且逐版下降（E） |
| 插件安装 | 每活跃用户的插件数 | ≥ 1.5（E） |
| 免费 → Pro 转化 | 付费 ÷ MAU | 基准 2–4%（E） |
| 同步开通率 | Pro 用户开启同步的比例 | ≥ Pro 的 50%（E） |
| AI 用量（第二阶段） | 每活跃 Pro 用户的 AI 命令数 | 与 §6 成本模型对账 |

北极星指标：**WAU**。启动器的生死取决于习惯频次；其余全是诊断项。

实施说明：事件在本地批量暂存，经用户选择加入后才离开设备；schema 带版本并公开；一个 CLI 开关（`--telemetry=off`)比藏起来的复选框更可靠；文件路径、查询文本、剪贴板内容永不离开设备——只上报计数与时长。

## 12. 18 个月路线图

| 版本 | 月份 | 范围 |
|---|---|---|
| **0.1 MVP** | M0–M2 | macOS + Windows：应用模糊搜索、剪贴板历史、片段、计算器、网页搜索 bang、系统命令、FPP1（JSON/stdio）插件协议；BUSL 公开仓库 |
| **0.2** | M3–M6 | 插件**画廊**（手工、精选）；**同步 beta**（设置 + 片段）；**Linux GTK4 宿主 beta**（Rivet 的 Linux 工作在此落地——这是全计划最大的工程风险）；FPP1 文档 + 10 个一方插件；Show HN |
| **0.3** | M7–M10 | **AI / BYOK**：用户密钥驱动的 AI 命令（对我们零推理成本）、片段编辑器、主题引擎、剪贴板规则；中文社区存在感（V2EX、少数派）；Paddle 计费集成（开关后台） |
| **1.0** | M11–M14 | **Pro 发布**：Pro + Teams 档经 Paddle 上线；**终身早鸟窗口开启（限售、不含 AI）**；精选商店基建（权限清单、审核流水线）；Product Hunt |

排序原则：平台完备先于 AI，AI 先于商店，商店先于中国。收入从 1.0 开始；在此之前的一切都为"可安装的可信度"服务。

每个里程碑的退出标准——即"完成"的定义：

- **0.1：** 两个平台可从 GitHub Releases 安装；FPP1 hello-world 插件以 Python 和 Rust 各写一遍并成文；我们机器上的无崩溃会话 ≥ 99%。
- **0.2：** 画廊上线十个一方插件；同步 beta 经受一次"抹掉并恢复"演练；Linux GTK4 宿主能启动并跑通 0.1 全部功能。
- **0.3：** BYOK AI 对接 OpenAI、Anthropic 与本地 Ollama 端点可用；经核实，我们服务端推理为零。
- **1.0：** Pro 经 Paddle 端到端可购买（税务代办、发票送达）；终身限额在授权逻辑中强制执行，而不是写在散文里。
- **1.1：** §7 的商店门槛要么达成，要么明显未达成并重新规划——路线图在本季度开始前就写明是哪一种。
